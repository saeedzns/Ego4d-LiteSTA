# Data Needed for notebooks/ego4d_sta_colab.ipynb (beyond ego4d_samples/v2)

This notebook can run in DEMO mode with synthetic data, but for a full run (DEMO=False) it needs your original Ego4D v2 assets on Drive. The `ego4d_samples/v2` folder only contains tiny schema samples — not the actual data. Below lists exactly what you must have and where.

## 1) Extracted Frames (images)
- What: Per-video frame images, typically written as `/content/drive/MyDrive/ego4d_data/v2/frames/<video_uid>/%07d.jpg` (0-based indices with 7-digit padding).
- Why: YOLO detector (Track A) and cropping for the head both work on images.
- Source: Your original videos (e.g., `/content/drive/MyDrive/ego4d_data/v2/videos/<video_uid>.mp4`). Extract with ffmpeg. The samples do not include images.
- Where found: The listing file `file_listings/ego4d_file_listing.csv` shows the root `/content/drive/MyDrive/ego4d_data/v2/`. Videos should be inside a `videos/` subfolder (or wherever your listing indicates).

## 2) Full STA Annotations (JSON)
- What: The complete Ego4D v2 STA annotations, not samples. At minimum:
  - `/content/drive/MyDrive/ego4d_data/v2/annotations/fho_sta_train.json`
  - `/content/drive/MyDrive/ego4d_data/v2/annotations/fho_sta_val.json`
  - (Optional) `/content/drive/MyDrive/ego4d_data/v2/annotations/fho_sta_test_unannotated.json`
- Why: To generate labels and manifests for detection and the head (verbs/nouns/TTC, ground-truth boxes, clip timing).
- Samples reference: `ego4d_samples/v2/annotations/fho_sta_{train,val}_json.csv` show the schema (e.g., `frame`, `clip_frame`, `action_*_frame`, `interval_*_frame`) but do not include the full dataset.

## 3) YOLO Detection Labels (TXT per image)
- What: YOLO-format label files aligned to your extracted frames (one `.txt` per image). Each line: `class cx cy w h` in normalized coords.
- Why: To train the YOLO stage (Track A) on the last frame’s next-active object (or your chosen noun class target).
- How to build: Convert STA annotations to YOLO labels for the corresponding frame images. Use the full JSONs in (2) and your frame extraction mapping.
- Notebook expectation: It looks for labels under either:
  - `/content/drive/MyDrive/ego4d_data/labels` or `/content/drive/MyDrive/ego4d_data/yolo_labels`, or
  - It builds a local dataset copy under `runs/data/yolo/` from whatever `FRAMES_DIR` and `YOLO_LABEL_DIR` you point it to.
- Not included in samples: Must be generated by you.

## 4) Head Manifests (JSON)
- What: Two JSON manifests the head uses:
  - `head_train.json` — items with: `{image, gt_box, verb_id, noun_id, ttc}`
  - `head_val.json` — items with: `{image, gt_box, candidates, verb_id, noun_id, ttc}`
- Why: The head (Stage B) needs ground-truth crops and labels, and candidate boxes for validation.
- How to build: Combine (a) STA ground truth from (2) with (b) detector candidates (see 5) and (c) your verb/noun/TTC mapping.
- Notebook expectation: DEMO mode writes synthetic versions; REAL mode expects you to provide these paths.
- Not included in samples: Must be generated by you.

## 5) Detector Candidates (Val) — Top‑K JSON
- What: `candidates_val_k{K}.json` produced by YOLO on the validation images:
  - Format: list of `{image, candidates: [{xyxy, score, noun}]}`.
- Why: Validation for the head uses proposals to select the top candidate.
- How to produce: Run the trained YOLO model on your val images (cell “Export Top‑K candidates”).
- Not included in samples: Produced by your run.

## 6) Taxonomies (verbs/nouns)
- What: Full noun/verb taxonomies for mapping narrations to canonical classes:
  - `/content/drive/MyDrive/ego4d_data/v2/annotations/narration_noun_taxonomy.csv`
  - `/content/drive/MyDrive/ego4d_data/v2/annotations/narration_verb_taxonomy.csv`
- Why: To produce consistent class indices for head/detector label space (if you map beyond a single “object” class).
- Samples reference: `ego4d_samples/v2/annotations/narration_{noun,verb}_taxonomy_csv.csv` show the schema; use full files for complete coverage.

## 7) Optional: FHO Main & Other Tasks (for metadata)
- What: Useful full JSONs for timing, keyframes, or cross-checks:
  - `/content/drive/MyDrive/ego4d_data/v2/annotations/fho_main.json` (video intervals and `critical_frames`)
  - Hands/SCOD/OSCC/NLQ/VQ/Moments JSONs if you want to augment labels or visualize.
- Why: To verify `num_frames`, timing consistency, and keyframes (e.g., `pre_45`, `pnr_frame`).
- Samples reference: see `ego4d_samples/_auto_fields.md` for which fields exist in each task file.

## Summary — What’s not in ego4d_samples/v2
- Frames: Images must be extracted from original videos (samples don’t include images).
- Full JSON annotations: Use complete v2 JSONs under `.../v2/annotations/` (samples only show a few records as CSV).
- YOLO labels: Per-image TXT files aligned to your frames (generate from full STA JSONs).
- Head manifests: Build `head_train.json` and `head_val.json` from STA + candidates.
- Candidates JSON: Produced by your detection stage.
