# Decision Record: Noun Class Alignment Strategy (Stage A Proposals)

Date: 2025-11-09  
Status: Accepted (baseline for Track A v2)  
Owner: Track A pipeline / Stage A–Stage B interface

## 1. Context
Stage B consumes candidate head crops (ROIs) generated by Stage A for downstream verb / noun / TTC reasoning. Current Stage A proposal generation uses generic object proposals (YOLO generic model or oracle labels) without a detector trained specifically on Ego4D noun taxonomy. Ego4D noun space is large, long‑tailed, and many classes have sparse bounding box supervision in the local subset. Engineering time is constrained; we have already instrumented recall@K evaluation and consolidated head manifests.

Key constraint: We need sufficiently *high recall* of relevant interaction regions (hands + manipulated objects) with *low incremental engineering cost*, while preserving future flexibility to specialize.

## 2. Problem
How should we align proposals to noun classes now?

Option A: Fine‑tune (or train) a YOLO variant directly on Ego4D noun classes (full or reduced mapping).  
Option B: Keep a *noun‑agnostic* generic proposal generator (current YOLO weights or oracle YOLO labels) and rely on downstream head model to classify noun ID from the crop.  
Option C (hybrid extension): Generic proposals + lightweight re‑ranking / filtering using open‑vocabulary or CLIP similarity to noun prompts (later, not now).  

## 3. Options Analysis
### A. Fine‑tune YOLO on Ego4D nouns
Pros:
- Potentially higher precision; may reduce negative crop volume.
- Can inject prior about noun shapes / context.
Cons:
- Requires curated bounding boxes per noun (data wrangling cost).
- Long tail: many noun classes will remain underfit → inconsistent recall.
- Training & hyperparameter tuning overhead; slows iteration on Stage B/Head.
- Risk of coupling detector updates with head model experiments (slower feedback loop).

### B. Generic proposals (current approach)
Pros:
- Zero extra labeling or training cost now.
- Maximizes *recall* when K is moderately large (we can sweep K, already instrumented).
- Decouples detector from noun taxonomy evolution and allows rapid iteration on semantic head.
- Reproducible & fast; stable baseline for ablations.
Cons:
- More negative / off‑target crops → class imbalance for head training.
- May miss small, fine‑grained nouns if generic detector bias differs.

### C. Hybrid (add open‑vocabulary / CLIP scoring later)
Pros:
- Incremental recall or precision gains without full detector fine‑tune.
- Can narrow candidates per noun dynamically; supports expansion.
Cons:
- Adds inference overhead (feature extraction + similarity scoring).
- Additional complexity before establishing baseline head performance.

## 4. Decision
Adopt **Option B: Maintain noun‑agnostic generic proposals** for the current Track A milestone. No immediate YOLO fine‑tuning on Ego4D noun taxonomy. We will treat noun classification as a *head task* operating over generic region proposals.

## 5. Rationale
- Primary metric we must unlock now is reliable recall@K; generic proposals already provide measurable recall (instrumented) without extra data engineering.
- Opportunity cost: Time spent assembling noun box annotations would delay validating verb/noun/TTC reasoning quality and temporal fusion logic.
- Risk management: Avoid overfitting detector to a sparse subset; defers taxonomy drift issues.
- Modularity: Keeps detector replaceable; later we can plug in improved proposal sources (OVD, SAM+classifier, fine‑tuned YOLO) without retraining the head architecture.

## 6. Expected Impact
- Slightly higher negative:positive ratio in consolidated `head_{train,val}.jsonl` (already observed ~6–7% positives). Acceptable; can be mitigated via sampler weighting or focal / logit-adjusted loss.
- Faster experiment velocity for head modeling and temporal reasoning.

## 7. Quantitative Guardrails & Metrics
We will periodically log:
- `recall_at_K` (already in Stage B). Target: ≥0.55 at K≤10 for frames with GT (initial baseline being collected—current oracle+generic recall lower; K sweep to inform K choice).
- `mean_best_iou` distribution: ensure tail above IoU 0.5 not collapsing when adjusting K.
- Positive ratio in consolidated head manifests: maintain ≥4% to avoid extreme imbalance; if it drops, consider adaptive K or mining.

If with K=10 recall remains <0.45 after data scaling, we trigger evaluation of hybrid (Option C) before committing to fine‑tune.

## 8. Revisit Triggers
Reconsider fine‑tuning (Option A) if ANY of:
1. Plateau: `recall_at_K < 0.55` for K=10 while head accuracy saturates.
2. Precision pressure: Training becomes compute‑bound due to excessive negatives (negative:positive > 25:1 leads to instability even with weighting).
3. New annotation tranche becomes available supplying ≥1k boxes for top 30 high‑frequency nouns.
4. Downstream error analysis shows consistent systematic misses of a *specific cluster* (e.g., small utensils) attributable to Stage A proposals.

## 9. Mitigations & Interim Enhancements (Non‑Blocking)
- K Sweep Automation: Already present (`oracle_k_sweep.py`); finalize runs to set default K (likely 8–10) balancing recall & crop volume.
- Hard Negative Mining: After first head training pass, feed false positives back as additional negatives (no detector change required).
- Weighted Sampling: Oversample positive crops or use class‑balanced loss to counter 6–7% positive ratio.
- Optional Future Hybrid: Add CLIP embedding scoring to re-rank top-N proposals before head ingestion (kept out of critical path for now).

## 10. Implementation Notes (No Code Changes Now)
- Stage A continues to expose K via `STAGEA_K` and mode via `STAGEA_MODE`.
- Stage B already emits recall metrics; decision recorded here suffices.
- No changes to `trackA_stageA.py` / `trackA_stageB.py` in this decision.

## 11. Alternatives Considered & Rejected (Brief)
- Immediate fine‑tune on subset of nouns: Rejected due to sparse labels + timeline.
- Replacing YOLO with open-vocabulary detector (e.g., GroundingDINO) now: Rejected; would add compute overhead and complexity before baseline stabilization.

## 12. Risks & Contingencies
| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Low recall for small objects | Medium | Increase K; add hybrid re-ranking; later fine‑tune subset. |
| Head overfits background bias | Medium | Data augmentation; hard negative mining. |
| Class imbalance hurts noun head | High | Loss re-weighting / focal loss / oversampling. |
| Drift when switching proposal strategy later | Medium | Keep manifests versioned; log detector provenance (already done). |

## 13. Summary
We prioritize speed and modularity: keep generic proposals, invest in head model improvements first, and defer detector specialization until quantitative guardrails signal need.
